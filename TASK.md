You are the coding lane for `yue2-rs`. The reviewer (claude-mini) reads your diff and

## Goal

A Rust crate `yue2` (this repo) that reproduces the Python package `yue2-infer 0.1.6`
end to end: request JSON -> ABC plan (AR) -> semantic tokens (AR) -> latents (NAR) ->
48 kHz stereo audio (VAE decoder). Inference backend: `candle` 0.11 (CUDA first,
CPU must also build and run the tests slowly). Library first, thin CLI second.
SheetSage2 / MERT2 (covers, audio -> ABC) is OUT of scope for v1.

## Fixed design decisions (do not relitigate; put objections in the report)

1. One crate, `yue2`, lib + `src/bin/yue2.rs`. Cargo features: `cuda`, `flash-attn`
   (candle-flash-attn), `metal`; default none (CPU). Edition 2021.
2. Modules: `tokenizer` (qwen.tiktoken via `tiktoken-rs` CoreBPE with the loaded
   ranks + the special tokens exactly as tokenization_yue2.py defines them),
   `protocol` (SongRequest, GenerationConfig, Sampling, `token_prefixes`,
   `negative_prefix`, CODEC_OFFSET — a byte-for-byte port of protocol.py),
   `model` (backbone: RMSNorm, RoPE, GQA attention, SwiGLU MLP, StaticKVCache,
   TimestepEmbedder, AudioPositionEmbedding, YuE2ForCausalLM), `sampling`
   (generate_tokens: temperature / top-p / top-k / repetition handling as in
   sampling.py, CFG negative prefix when guidance != 1), `nar` (CachedNAR /
   synthesize), `vae` (Oobleck decoder: weight-normed Conv1d / ConvTranspose1d,
   SnakeBeta, ResidualUnit, DecoderBlock; fold weight-norm g/v into a plain
   weight at load time), `pipeline` (plan -> semantic -> latents -> audio as four
   public functions plus `generate(request)`), `storage` (write the same output
   files as Python: score.abc, plan.json, semantic.npy, latent.npy, audio.flac or
   wav, result.json).
3. Weights are loaded from explicit directories (`--model-dir`, `--vae-dir`), defaulting
   to the HF snapshot paths above via `HF_HOME`. Use `safetensors` + candle
   VarBuilder. Never convert or copy the weights.
4. Numerics: bf16 on CUDA for the backbone as Python does; f32 for the VAE as
   Python does. RNG: candle's own seeded RNG. Sampling parity is NOT expected to be
   bit-exact with torch; logits parity under teacher forcing IS (see gates).
5. Parity fixtures are generated by `tools/dump_reference.py` (Python, runs in the
   torch venv) into `~/work/yue2-rs-fixtures/` as **safetensors** files (candle
   reads them natively) plus small JSON sidecars. Fixtures are NOT committed;
   `.gitignore` them. Rust integration tests read `YUE2_FIXTURES` env var and
   `#[ignore]`-skip cleanly when it is unset.
6. Attention: start with plain candle sdpa (matmul + softmax) and a causal mask;
   flash-attn behind the feature flag. CUDA graphs and fast.py tricks are OUT of
   scope until Phase 5.
7. No new Python beyond `tools/`. No network at build or test time except crates.io.
8. Every phase ends with `REPORT-P<n>.md` at repo root: what was done, the exact
   commands run with their pasted output for each gate, the unsure list, objections
   to the design, and a self-audit (re-run each gate once more from a clean
   `cargo test` and confirm the numbers you quote are from that run).

## Phases and gates

### Phase 0: fixtures and skeleton
- `tools/dump_reference.py`: for the first-song request, dump under
  `~/work/yue2-rs-fixtures/first-song/`:
  - `tokens.safetensors`: prefix ids, abc ids, semantic ids (from the existing
    .npy files), plus the exact token id list the tokenizer produces for 20 short
    probe strings (ASCII lyrics, section tags, ABC lines, non-ASCII text) and the
    special token ids.
  - `ar_logits.safetensors`: teacher-forced logits (f32) of the backbone for the
    first 64 positions of `prefix + abc_ids` and, separately, the hidden state after
    embedding, after layer 0, after layer 13, after the final norm for those
    positions. Use the plain eager path (not cuda_graph / fast).
  - `nar.safetensors`: the NAR inputs and outputs for the first 2 chunks of the
    reference semantic tokens: the noise tensors used (seeded), every intermediate
    the CachedNAR loop produces per step, and the final latents for those chunks.
  - `vae.safetensors`: reference latents (all) and the decoded audio (f32) for the
    first 4 seconds, plus the output of each DecoderBlock for a 64-frame latent
    slice.
  - `manifest.json`: shapes, dtypes, seeds, the sha256 of the two model.safetensors.
  - Total budget <= 1.5 GB. Print sizes.
- Cargo skeleton that builds on CPU with `cargo build` and with `--features cuda`.
- Gate P0: the dump script runs end to end; `cargo build --features cuda` succeeds;
  `cargo test` runs (0 real tests yet is fine).

### Phase 1: tokenizer + protocol + AR backbone under teacher forcing
- Gate P1a: for all 20 probe strings and the full first-song prefix, Rust token ids
  == Python token ids exactly; decode(encode(s)) == s.
- Gate P1b: `token_prefixes(request)` == Python `prefix.npy` exactly for the
  first-song request and for the two other request JSONs in
  `~/yue2/outputs/song2/request.json` and `song3/request.json` (dump their prefixes
  in Phase 0 too).
- Gate P1c: teacher-forced logits: argmax matches Python at all 64 positions;
  max |logit diff| <= 0.5 in bf16 and hidden-state cosine similarity >= 0.999 at
  each dumped layer. Report the actual numbers.
- Gate P1d (CLARIFIED 2026-09-14, owner decision): greedy decode of the ABC plan
  from the prefix, 64 steps, equals the first 64 tokens of the Python GREEDY dump
  (`--greedy`); this is the gate. The comparison against the original SAMPLED
  `abc_tokens.npy` (61/64, ties at steps 16/17/26 per REPORT-P1) is advisory: keep
  the test, report the count, do not fail on it.

### Phase 2: AR sampling + full plan and semantic generation
- Gate P2a (ADVISORY since 2026-09-14, owner decision: sampling is not bit-exact by
  design, so structural identity of a sampled plan is reported, not required): with
  the same seed and sampling params, generate a full plan; the ABC must parse; report
  its section tags next to the reference tags, the key/meter line count, and the
  length ratio (target within 30%). Only "does not parse" fails the gate.
- Gate P2b: semantic tokens generated from the Python plan (teacher-forced plan,
  sampled semantic): token count within 20% of `semantic.npy`, codec-offset range
  valid, truncation flags handled as in pipeline.py.
- Gate P2c: throughput measured on GPU 0 and reported (tok/s for plan and semantic).
  The 162/186 tok/s figures in result.json were measured with execution=cuda_graph
  and attention=flash, NOT eager. Measure the Python EAGER number yourself once
  (execution=eager, same GPU, same request) and report both comparisons.

### Phase 3: NAR
- Gate P3 (REWORDED 2026-09-14 by the owner after REPORT-P3b.md: FP32 paired runs
  agree to 2e-5, so the algorithm is faithful and the bf16 trajectory difference is
  backend rounding amplified over 64 velocity steps). Two tiers, both required:
  (a) algorithmic parity: with identical checkpoint values, dumped noise, original
  chunk boundaries and 32 midpoint steps, a paired FP32 Python/Rust run has final
  max |diff| <= 1e-3 and cosine >= 0.999999 per chunk; (b) production CUDA BF16
  against the original Python BF16 oracle: cosine >= 0.999 per chunk, and REPORT
  the max |diff|, the native stage dtypes and the first divergent operation. The
  BF16 max |diff| bound is advisory (report it, do not fail on it).

### Phase 4: VAE decoder
- Gate P4a: per-DecoderBlock outputs match within max |diff| <= 1e-3.
- Gate P4b: decoding the reference latents gives audio with SNR >= 40 dB against
  the reference audio over the first 4 seconds; write a wav and a flac.

### Phase 5: pipeline, CLI, speed
- `yue2 generate --request req.json --output DIR` producing the same file set as
  Python. `yue2 plan`, `yue2 render --abc-file` for edits/covers-from-ABC.
- Gate P5: end-to-end run of the first-song request; report wall time per stage vs
  Python (59.4 s audio in 19.6 s wall with fast path; eager numbers from your own
  Python measurement).
